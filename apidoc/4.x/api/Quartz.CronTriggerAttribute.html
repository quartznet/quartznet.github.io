Remarks

The expression is read at build time with the parser that reads it at run time, so one that cannot parse is QZ0001 rather than an exception while the host starts. H is resolved against the trigger's key, exactly as it is for WithCronSchedule — see cron expressions.

This attribute says nothing on a class that does not also carry QuartzJobAttribute, and the generator reports QZ1003 rather than letting a schedule be declared and silently ignored.

What it cannot say — a start or end time, a calendar, job data, a retry policy, a preferred node — is what AddTrigger<T> is for, and the two live together: a declared job can be given further triggers by hand.

Properties

ConfigurationKey

A configuration key whose value, when it is set, is the cron expression the trigger fires on instead of CronExpression. Defaults to none: the schedule is the attribute's.

public string? ConfigurationKey { get; init; }

Property Value

string

Remarks

Read from the container's IConfiguration as the scheduler is built, so "Jobs:Cleanup:Cron" is the Cron value of the Jobs:Cleanup section, or the environment variable Jobs__Cleanup__Cron. The constructor's expression stays required: it is checked at build time like any other, and it is the schedule wherever the key is not set or no IConfiguration is registered.

A configured value is not checked at build time. It is parsed as the scheduler is built, so one that does not parse, an empty one included, stops the host from starting with the parser's message rather than leaving a schedule that never fires.

TimeZone

The time zone the schedule is read in, by the id FindById(string) resolves — an IANA id such as "Europe/Helsinki" or a Windows one such as "FLE Standard Time". Defaults to the scheduler's local time zone.

public string? TimeZone { get; init; }

string

Remarks

Resolved when the registration runs rather than at build time: the build machine's zone database is not the run-time machine's, and an analyzer refusing a zone your server has would be worse than no analyzer.
