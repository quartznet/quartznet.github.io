Interface IQuartzDashboardHubClient

Namespace
Quartz.Dashboard.Hubs
Assembly
Quartz.Dashboard.dll

The events the dashboard hub pushes to a connected browser.

public interface IQuartzDashboardHubClient

Remarks

Nothing outside this assembly calls this, and its DTOs are of no use to anyone else either, so it would be internal if it could be. It cannot: SignalR reaches a typed client by emitting a proxy into a dynamic assembly of its own, which no InternalsVisibleTo can name — a strong-named assembly may only grant one to a friend it names by public key — and the proxy then fails to load with "attempting to implement an inaccessible interface". QuartzDashboardHubClientProxyTest is the guard.

The Task return types are dictated by SignalR for the same reason: the typed-client proxy only implements members returning Task or Task<TResult>.

Every payload leads with the SchedulerInstanceId of the node that raised the event. A browser joins a group named after a scheduler, and in a cluster that group is fed by every node running that scheduler — so without the id a live view cannot say which machine an event came from, which is what https://github.com/quartznet/quartznet/issues/3422 reported. A pause and a resume get a payload of their own for it rather than a JobKeyDto / TriggerKeyDto: those are keys, used by IQuartzApiClient everywhere, and a key does not belong to a node.
