Remarks

The agent is a plugin: UseDashboardAgent installs it on one scheduler, and that scheduler opens one outbound connection to Endpoint — the dashboard's agent hub — and keeps it open for as long as it runs. The dashboard then lists the scheduler as Agent, under the key {Target}/{scheduler name}, and drives it through that connection: every page, every action, the execution history and the live events.

The connection crosses a trust boundary by design, and the narrowings here are the only ones that hold against a dashboard that has been taken over: ReadOnly, IsOperationAllowed and IsJobTypeAllowed are the agent's own decisions, made in the worker's process, and nothing the dashboard sends can widen them. The dashboard's own ReadOnly hides its buttons; it does not bind an agent.

IsJobTypeAllowed

Which job types a request through this agent may name. null — the default — refuses every one: an agent crosses a trust boundary, and with Quartz.Jobs on the probing path a dashboard that may name any IJob may run any executable on this machine.

public Func<string, bool>? IsJobTypeAllowed { get; set; }

Property Value

Func<string, bool>

Remarks

Only the operations that store a job by type name are refused — add-job, schedule-job with a job, and schedule-jobs. Triggering, pausing, rescheduling and deleting a job the scheduler already holds work with the predicate unset. The refusal is 403 with problem details naming this option as the remedy.

The predicate is given the job type name as it was written, and nothing resolves it first — the name is data until the scheduler loads it. Match on the string, and remember that one type has more than one spelling: Acme.Jobs.Nightly, Acme.Jobs and the same name carrying Version, Culture and PublicKeyToken are both it. A StartsWith on the namespace covers every spelling at once. The HTTP API's QuartzHttpApiOptions.IsJobTypeAllowed is the same predicate with the opposite default, because that surface is on the application's own network.

Target

The name this process registers under, which is the first half of its scheduler's key on the dashboard. Defaults to MachineName. Cannot contain / or +.

public string? Target { get; set; }

Property Value

string

Remarks

Two processes cannot share a target: the second to connect is refused until the first is gone, and an agent that reconnects under the same target and the same scheduler instance id takes its own entry over. Give each process a target of its own where the machine name is not one — containers that restart under new names, or several workers on one machine.
