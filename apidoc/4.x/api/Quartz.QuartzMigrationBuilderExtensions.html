Remarks

On SQLite it creates the four delete triggers that clear a trigger's detail rows on a connection that does not enforce foreign keys. On MySQL it creates the acquisition index again with its descending PRIORITY column, which Oracle's MySQL provider leaves out when it creates the index. On PostgreSQL, SQL Server, Oracle and Firebird it adds nothing.

It is safe to run again: the triggers are created only where they are missing, and the index is replaced by the same index. A SQLite migration that rebuilds QRTZ_TRIGGERS drops its triggers, and ends with this call to put them back.

MoveQuartzTablesFromAppAny(MigrationBuilder, Action<QuartzTablesOptions>?)

Brings a schema AppAny.Quartz.EntityFrameworkCore.Migrations 0.6.3 created to the one AddQuartzTables models. It is the body of Up in the one migration that switches packages.

public static MigrationBuilder MoveQuartzTablesFromAppAny(this MigrationBuilder migrationBuilder, Action<QuartzTablesOptions>? configure = null)

Returns

MigrationBuilder

The same migration builder, for chaining.

Remarks

It repairs what that schema has wrong: the three execution-history indexes it never created, everywhere; on SQL Server, the NOT NULL on QRTZ_SIMPROP_TRIGGERS.STR_PROP_1 to STR_PROP_3, which Quartz writes NULL to, and the 150-character QRTZ_FIRED_TRIGGERS.INSTANCE_NAME. It creates what Quartz added since: QRTZ_TRIGGER_STATUS, which 4.9's execution history keeps.

It converges what the database changes in place, never narrowing a column: on SQL Server, QRTZ_FIRED_TRIGGERS.IS_NONCONCURRENT becomes nullable; on PostgreSQL and SQL Server, the foreign keys take the job store's delete rules. What differs in spelling only, would narrow a column, or would rewrite or rebuild a table is left as it is, so no table is rebuilt. Then it does what CompleteQuartzSchema(MigrationBuilder, Action<QuartzTablesOptions>?) does.

Scaffold the migration after replacing the AppAny model with AddQuartzTables, given the prefix and the schema the AppAny model used, and replace the body of Up with this call. The move is one-way: empty Down, which EF Core wrote as the whole difference reversed. The snapshot then holds this package's model, and every later migration only adds.

Exceptions

NotSupportedException

The migration's provider is not one Quartz has a model for, or is Oracle's or Firebird's, of which AppAny has none.

ArgumentException

The prefix holds what an unquoted identifier cannot or makes a name too long for the database, the schema is set for a database without schemas, or the identifier length is set, which is Firebird's alone.
