AddQuartzTables(ModelBuilder, string?, Action<QuartzTablesOptions>?)

Adds the job store's tables to this model, so that dotnet ef migrations add creates them, and after a Quartz upgrade adds what the release added.

public static ModelBuilder AddQuartzTables(this ModelBuilder modelBuilder, string? providerName, Action<QuartzTablesOptions>? configure = null)

Parameters

modelBuilder ModelBuilder

The model being built.

providerName string

The EF Core provider's name: Database.ProviderName.

Sets the table prefix and the schema, which must name the job store's tables, and on Firebird the longest name the database takes.

Returns

ModelBuilder

The same model builder, for chaining.

Remarks

Call it from OnModelCreating with Database.ProviderName. The provider decides the dialect: PostgreSQL (Npgsql), SQL Server, MySQL (Oracle's MySql.EntityFrameworkCore or Pomelo), SQLite, Oracle and Firebird. The tables are the ones SchemaProvisioning.CreateIfMissing creates, generated from the same model.

The migration that creates the tables ends with migrationBuilder.CompleteQuartzSchema(), which adds the part of the schema an EF Core model cannot say.

The tables are the job store's: nothing in the model is meant to be queried or written through EF Core.

Exceptions

ArgumentNullException

No provider is configured.

NotSupportedException

The provider is not one Quartz has a model for.

ArgumentException

The prefix holds what an unquoted identifier cannot or makes a name too long for the database, the schema is set for a database without schemas, or the identifier length is set for a database other than Firebird or outside 31–63.
