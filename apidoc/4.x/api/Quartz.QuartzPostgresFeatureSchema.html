Remarks

This is the join mode: opts.Storage.Add(QuartzPostgresFeatureSchema.ForScheduler(services)) inside ConfigureMarten. Marten then creates and migrates Quartz's tables whenever it applies its own — at startup, in db-apply, in resources setup — and Quartz registers no database of its own. Call either this or UseWeaselForPostgres for one scheduler, never both.

A feature schema rather than StoreOptions.Storage.ExtendedSchemaObjects: Marten's CompletelyRemoveAllAsync drops every extended schema object with CASCADE, which would take the schedule with it; a feature schema is left alone.

The tables are the same objects UseWeaselForPostgres applies: add-only, spelled the way PostgreSQL's catalog reads them back, and with the index names 3.x created and 4.x retired dropped.
