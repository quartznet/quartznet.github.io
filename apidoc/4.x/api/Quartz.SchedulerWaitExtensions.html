Remarks

Extensions rather than IScheduler members, so no interface grows. They need the scheduler Quartz builds, the IScheduler the container injects, a DelegatingScheduler over one, or HttpScheduler; any other scheduler is refused with NotSupportedException.

The wait is keyed by the trigger. It answers the trigger's next final completion after the wait begins, or, for a trigger already gone, its newest final row in the execution history. A retried occurrence ends at its last attempt. A veto and a firing the job never ran for end the wait too.

In process the run shell answers it as the store commits the completion: when the wait returns, a one-off is gone and a DisallowConcurrentExecutionAttribute block is lifted. On a cluster the firing may run on another node, so the wait reads the execution history every node writes, UsePersistentStore(store => store.UseExecutionHistory()), and the trigger's state: from 200 ms apart, doubling to 5 s. A cluster without that history is refused before anything is stored. Over HttpScheduler it reads the host's history and trigger routes the same way.

The timeout stops the wait and never the job: a wait that runs out answers Pending with the key to wait again with. Zero looks once, and InfiniteTimeSpan has no limit. It is measured on the system clock, whatever clock the scheduler keeps. The token throws OperationCanceledException and leaves the job alone. A wait still open when the scheduler shuts down throws SchedulerException.

TriggerJobAndWait(IScheduler, JobKey, JobDataMap?, TimeSpan, CancellationToken)

Fires the stored job now with the given data and waits up to timeout for how its run ended.

public static ValueTask<FiringResult> TriggerJobAndWait(this IScheduler scheduler, JobKey jobKey, JobDataMap? data, TimeSpan timeout, CancellationToken cancellationToken = default)

Parameters

scheduler IScheduler

The scheduler to fire the job on.

jobKey JobKey

The stored job to fire.

data JobDataMap

The firing's own job data, or null for none.

timeout TimeSpan

How long to wait; it stops the wait, never the job.

cancellationToken CancellationToken

The cancellation instruction; it stops the wait, never the job.

Returns

ValueTask<FiringResult>

How the firing ended, or Pending when the timeout ran out first.

Remarks

The firing TriggerJob(JobKey, JobDataMap?, CancellationToken) makes: a one-shot trigger named MT_ and a number in the default group, marked manual, in the execution group TriggerJob would give it. Its key is on TriggerKey. The map is copied onto the trigger; the one passed in is left as it was.

Exceptions

ArgumentNullException

scheduler or jobKey is null.

ArgumentOutOfRangeException

timeout is negative and is not InfiniteTimeSpan.

NotSupportedException

The scheduler cannot wait for a firing, or it is clustered without a history every node writes. Nothing is stored.

SchedulerException

The scheduler has been shut down, or shut down while waiting.

JobPersistenceException

No job is stored under jobKey.

WaitForFiring(IScheduler, TriggerKey, TimeSpan, CancellationToken)

Waits up to timeout for how the next firing of the trigger ends, or, for a trigger already gone, for what its newest row in the execution history says.

public static ValueTask<FiringResult> WaitForFiring(this IScheduler scheduler, TriggerKey triggerKey, TimeSpan timeout, CancellationToken cancellationToken = default)

Parameters

scheduler IScheduler

The scheduler the trigger is stored in.

triggerKey TriggerKey

The trigger whose firing to wait for.

timeout TimeSpan

How long to wait; it stops the wait, never the job.

cancellationToken CancellationToken

The cancellation instruction; it stops the wait, never the job.

Returns

ValueTask<FiringResult>

How the firing ended, or where the wait stood when it answered.

Remarks

The second half of TriggerJobAndWait: after Pending, wait again with TriggerKey. Also the wait for a trigger stored another way, such as by TriggerJob<TInput>(IScheduler, JobKey, TInput, CancellationToken) or the named-key TriggerJob(IScheduler, JobKey, JobDataMap?, TriggerKey, CancellationToken).

A firing that ended before the wait began is read from the execution history. Without one it answers Unknown, as it does for a trigger unscheduled or whose job was deleted while waited on, and for a row retention has trimmed.

The timeout stops the wait and never the job, as the token does.

Exceptions

ArgumentNullException

scheduler or triggerKey is null.

ArgumentOutOfRangeException

timeout is negative and is not InfiniteTimeSpan.

NotSupportedException

The scheduler cannot wait for a firing, or it is clustered without a history every node writes.

SchedulerException

The scheduler has been shut down, or shut down while waiting.
